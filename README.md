# 손익계산서 IFRS 18 변환

## 프로젝트 소개

1. **기존 손익계산서(Excel)를 IFRS 18의 새로운 표시체계에 맞춰 재구성하는 Python 자동화 도구입니다.**
2. **연결재무제표 주석과 사업보고서**를 활용해 계정별 분류 근거와 검증 결과를 정리합니다.
3. 분류 범주를 판단할 때 사용한 **원천자료(주석·사업보고서), 판단 근거, 관련 IFRS 기준서 문단**을 각각 별도로 표시합니다.
4. 분류 범주가 명확하지 않은 계정과목은 판단을 위해 필요한 **증빙 및 추가자료**를 표시합니다.
5. 단순히 표의 모양만 바꾸는 것이 아니라, 각 수익·비용 계정의 성격을 검토해 **영업·투자·재무·법인세·중단영업** 범주로 분류하고 **영업손익·재무손익 및 법인세비용차감전손익·당기순손익** 등 주요 합계를 표시합니다.

### 한눈에 보는 처리 과정

**기존 Excel 손익계산서 → OpenDART 공시·주석 확보 → 규칙 기반 1차 분류 → AI의 근거 기반 재분류 → 자동 검증·결과 Excel 생성**

| 단계 | 수행 내용 |
| --- | --- |
| **① 기존 손익계산서의 계정과 금액을 읽고 분석 대상을 구성** | Excel에서 **계정과목, 당기·전기 금액, 설명·주석** 등 필요한 열을 인식합니다. 수익·비용의 부호와 단위를 반영하고, 매출액·영업손익·당기순손익 같은 **중간합계·통제행을 상세 계정과 구분**하여 중복 집계되지 않도록 준비합니다. |
| **② OpenDART에서 실제 공시 원문을 수집하고 계정별 판단 자료를 연결** | 공시 접수번호를 기준으로 **사업보고서와 선택한 연결(CFS)·별도(OFS) 감사보고서**를 가져옵니다. 각 계정과 관련된 **번호별 주석의 표·설명, 해당 주석이 참조하는 다른 주석, 사업보고서의 ‘사업의 내용’**을 연결합니다. AI가 근거를 추적할 수 있도록 원문 내용과 출처·문서 위치를 함께 전달합니다. |
| **③ 명확한 계정은 회계기준 규칙으로 분류하고, 불명확한 계정은 AI가 경제적 실질을 분석** | 우선 Python의 분류 규칙을 적용합니다. **외환손익·기타손익 등 명칭만으로 범주를 정하기 어려운 계정**은 AI에 묶어 전달하여 **발생 원천, 거래의 성격, 회사의 주된 사업활동 및 K-IFRS 제1118호 문단 요약**을 종합 검토합니다. AI는 **영업·투자·재무·법인세·중단영업** 중 적절한 범주와 판단 이유, 근거 인용 및 관련 문단을 **구조화된 형식**으로 제안합니다. |
| **④ AI가 추가 증빙을 탐색하도록 하고, 제안 결과를 Python이 교차 검증** | 제공된 정보만으로 판단하기 어려우면 AI가 **추가로 필요한 주석을 지정**하고, 프로그램은 해당 원문을 더 제공해 **최대 2차례 재판단**합니다. 이후 Python이 **원본 계정명·금액 일치, 인용문이 실제 원문에 존재하는지, 기준서 문단 번호와 출처 위치**를 검증합니다. 확인된 분류만 **자동 반영**하고, 원천 미확인 또는 여러 범주가 혼합된 계정은 **판단 보류**로 남겨 필요한 계정명세·증빙을 제시합니다. |
| **⑤ IFRS 18 손익계산서를 생성하고 대사 결과와 판단 근거를 함께 출력** | 분류 결과를 바탕으로 **영업손익 → 재무손익 및 법인세비용차감전손익 → 법인세비용차감전손익 → 당기순손익**의 구조를 가진 손익계산서를 생성합니다. 원래 시트는 보존하면서 **계정재분류·공시IS_IFRS18·검증결과·분류근거** 시트를 추가하고, 공시가 수집된 경우 **공시원문근거**도 남깁니다. 미분류 금액과 원본 순손익 대비 차이를 표시해 **AI의 판단 결과를 사람이 다시 검토할 수 있도록** 합니다. |

> **AI의 역할:** AI가 모든 계정을 임의로 결정하는 방식이 아니라, **규칙만으로 판단하기 어려운 항목의 원천과 근거를 분석하고 추가 주석을 요청**합니다. 분류의 채택 여부와 금액·인용 검증은 Python이 담당합니다. AI 연결이나 공시 근거가 부족하면 무리하게 확정하지 않고 검토 대상으로 남깁니다.

**원본 보호:** 기존 Excel 파일과 원본 시트는 그대로 두고, 변환 결과를 별도 파일로 저장합니다. 원천 정보가 부족하거나 여러 범주가 섞인 계정은 임의로 분류하거나 금액을 배분하지 않습니다.

**실행 방식:** 별도 화면 프로그램(GUI) 없이 명령어로 실행합니다. Python 3.11 이상을 사용하며, Windows / Python 3.12에서 실행을 확인했습니다. 공시 자동 수집과 AI 분석에는 각각 OpenDART·OpenAI API 키가 필요합니다. 키가 없거나 기능을 생략한 경우에도 가능한 범위에서 Excel을 생성하고 미확정 항목을 표시합니다.

## 설치

압축을 풀고 해당 폴더의 PowerShell에서 실행합니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

`.env`에 OpenAI 인증키와 계정에서 사용 가능한 Structured Outputs 지원 모델명을 넣습니다. OpenDART 키와는 다른 키입니다.

```dotenv
OPENAI_API_KEY=발급받은_OpenAI_API_키
OPENAI_MODEL=사용할_모델명
OPENDART_API_KEY=발급받은_40자리_OpenDART_키
```

키가 없거나 호출에 실패해도 Excel 생성은 계속합니다. 해당 계정은 ‘판단 보류’와 필요한 자료를 표시합니다. 키·API 예외 원문은 출력하지 않습니다. AI를 사용하면 계정명·금액·설명과 관련 주석 원문·사업활동이 OpenAI API로 전송됩니다. 원본 통합문서 전체를 업로드하지 않습니다.

## 사업보고서·주석 자동 수집

입력 Excel에 DART 공시 링크가 있으면 접수번호를 자동 인식합니다. 없으면 `--rcept-no`로 같은 사업보고서의 접수번호를 지정하세요.

```powershell
.\.venv\Scripts\python.exe convert.py "기존손익계산서.xlsx" --company "삼성전자" --year 2025 --activities "전자제품 제조 및 판매" --rcept-no 20260310002820 --output "주석반영.xlsx"
```

- `document.xml` 한 번으로 사업보고서와 감사보고서를 가져와 `cache/`에 저장합니다. 재실행 때는 캐시를 사용합니다.
- 기본은 연결 주석(CFS)입니다. 별도 자료는 `--fs-div OFS`를 사용합니다. 계정 원천은 해당 감사보고서에서만 검색해 연결·별도 주석 혼입을 막습니다.
- 계정별 관련 주석 전체와 그 주석이 참조하는 주석, 사업 내용의 절별 원문을 제공합니다. 최초 판단은 일괄 요청하며 필요한 추가 주석이 있으면 최대 두 차례 추가 조회·판단합니다. API 오류 자체는 재시도하지 않습니다.
- 문서명·문자 위치·공시 링크와 인용문을 기록합니다. 입력 공시와 지정 접수번호가 다르면 중단합니다. 회사명 불일치는 주석을 적용하지 않고 안내합니다.
- 관련 주석과 사업 내용으로도 필요한 원천 구분을 확인할 수 없거나 통합 계정이 여러 범주에 걸치면 임의로 한 범주에 넣지 않습니다. 필요한 명세·증빙 또는 분할 필요성을 표시합니다.
- 주석 수집을 생략하려면 `--no-documents`, AI 호출을 생략하려면 `--no-ai`를 사용합니다.

## 실행

입력 Excel에 `계정과목`, `당기`, `전기`, `주석`처럼 명확한 열 제목이 있으면 자동으로 찾습니다. 입력의 금액은 원 단위, 수익은 양수·비용은 음수로 준비합니다.

```powershell
.\.venv\Scripts\python.exe convert.py "기존손익계산서.xlsx" --company "기업명" --year 2025 --activities "자동차 부품 제조 및 판매" --output "변환결과.xlsx"
```

인식이 안 되거나 표가 여러 개라면 시트·헤더행·열을 지정합니다.

```powershell
.\.venv\Scripts\python.exe convert.py "기존손익계산서.xlsx" --company "기업명" --year 2025 --activities "제품 제조 및 판매" --sheet "공시 IS" --header-row 11 --account-col C --current-col D --output "변환결과.xlsx"
```

전기 금액 열이 E라면 `--previous-col E`를 추가합니다. 백만원 단위 표는 `--scale 1000000`, 비용을 양수로 적은 표는 `--expenses-positive`를 추가합니다. 이 옵션은 원가·비용·손실 명칭을 음수로 바꾸므로 금액 부호를 반드시 확인하세요. 원래 부호가 있으면 기본 옵션을 사용합니다.

API 호출 없이 확인:

```powershell
.\.venv\Scripts\python.exe convert.py examples/input_example.xlsx --company "가상제조" --year 2025 --activities "제품 제조 및 판매" --no-ai --output "가상제조_변환.xlsx"
.\.venv\Scripts\python.exe -m pytest -q
```

입력에 계산 수식이 있지만 Excel이 저장한 계산값이 없다면 임의 계산하지 않고 입력 확인으로 표시합니다. 원본을 Excel에서 재계산·저장하거나 숫자로 된 입력표를 사용하세요.

## 결과 확인

기존 시트들에 다음 네 시트가 추가되며, 공시를 수집하면 ‘공시원문근거’ 시트도 만듭니다.

- **계정재분류**: 규칙 분류, AI 추천, 판단 근거, 문단, 원천자료, 필요한 증빙을 나란히 표시합니다. 근거가 확인된 AI 분류는 자동 반영됩니다. 필요한 경우 M열에서 분류를 수정할 수 있습니다.
- **공시IS_IFRS18**: 영업·투자·재무·법인세·중단영업과 중간합계, 당기순손익을 작성합니다. OCI는 별도 표시합니다. 미분류 금액도 별도로 보여줍니다.
- **검증결과**: 원본 순손익과 변환 순손익, 원본 상세 합계, 미분류·미검토 계정을 확인합니다.
- **분류근거**: 적용한 규칙과 문단을 정리합니다.

근거 검증을 통과한 AI 분류는 **자동 적용**되며 사용자 승인은 요구하지 않습니다. 근거가 없으면 분류를 만들지 않고 ‘판단 보류’로 남깁니다. 예를 들어 외환차익은 매출채권·차입금 등 발생 원천별 명세가 필요하다고 표시합니다.

모든 상세 금액과 당기순손익 통제 금액이 있고, 미분류 항목이 없고, 손익 대사가 맞을 때만 자동 분류 완료로 표시합니다. 원본 중간합계와 당기순손익은 상세 계정에 중복 합산하지 않습니다. 부모 합계와 세부 내역이 함께 있는 표는 한쪽만 입력하거나 행유형 열에 `subtotal`을 지정하세요.

Excel 수식은 파일을 열 때 재계산됩니다. openpyxl 자체는 수식을 실행하지 않으므로 수식을 계산하지 않는 미리보기에서는 비어 보일 수 있습니다. M/N열 변경은 Excel의 계산식으로 손익계산서와 검증에 반영됩니다. 원천 설명·금액을 바꿔 AI 판단을 새로 받으려면 원본을 고친 뒤 새 파일명으로 다시 실행하세요.

## 입력의 선택 열

`기존범주`, `설명`, `주석`, `원천유형`, `행유형`을 추가하면 더 정확히 읽습니다. 기존 영업·영업외 구분은 새 분류를 확정하는 근거로 쓰지 않습니다.

원천유형은 경제적 실질을 확인한 경우만 입력합니다. 예: `operating_ppe`(영업에 쓰는 설비), `equity_method`(지분법), `loan_funding`(일반 차입), `lease_interest`(리스 이자), `trade_receivable_fx`(매출채권 외환), `loan_fx`(차입금 외환), `cash_equivalent`, `independent_asset`, `customer_funding`. 설명이나 주석 없이 원천코드만 적으면 분류를 보류합니다.

주된 사업활동은 반드시 입력합니다. 금융제공·투자가 주된 사업이면 `--finances-customers`, `--invests-assets`, `--invests-financial-assets`를 사용할 수 있습니다. 금융업은 명칭만으로 관련 부채·현금·정책 선택을 확정하지 않고 추가 확인 대상으로 남깁니다.

복수 원천이 섞인 계정은 원본에서 원천별 행으로 나눠 입력하고 합계행은 `subtotal`로 표시하세요. 단일 비조달 부채에서 발생한 외환차이를 임의로 복수 범주에 배분해서는 안 됩니다(문단 B67). 이 간단 버전에는 별도의 금액 분할 화면을 두지 않았습니다.

## 코드와 예제

`convert.py`가 실행 파일입니다. `ifrs18/parser.py`가 Excel을 읽고, `engine.py`와 `rules.json`이 규칙 분류를 하며, `ai.py`가 애매한 계정의 구조화된 추천을 검증합니다. 수식 생성과 Excel 저장은 `convert.py`에 모았습니다.

`examples/input_example.xlsx`와 `output_example.xlsx`는 가상 자료입니다. 외환차익은 API 없이 실행했으므로 판단 보류인 것이 예상 결과입니다. 사용자 확인 전의 예제 결과를 완료된 실제 공시로 제시하지 마세요.

사용자가 지정한 무료 체험판의 ‘양식변동 예시’와 ‘공시 IS’를 분석해 영업·투자·재무 범주 및 중간합계 구조를 참고했습니다. 타인의 강의자료는 배포 ZIP에 포함하지 않았습니다. 기준서 합계는 원본 예제 수식을 그대로 복제하지 않고 새로 계산합니다.

## 기준과 범위

K-IFRS 제1118호 문단 47, 49, 52~68, 69~74, B65~B67과 국내 한132.4~한132.5를 확인했습니다. 영업손익과 투자손익을 합한 뒤 재무손익을 더하는 누적 구조로 작성합니다. 고객 금융제공 기업의 문단 73 예외 등 복잡한 정책 판단은 전문 검토가 필요합니다. 전체 표시·주석 요구사항 준수를 보증하는 도구는 아닙니다.

## 주석과 사업보고서를 사용하는 방법

공시 원문의 연결·별도 감사보고서를 구분하고, 계정과 관련된 번호별 주석의 표와 설명 전체를 읽습니다. 주석에서 다른 주석을 참조하면 해당 주석도 가져옵니다. 사업보고서는 ‘II. 사업의 내용’의 절별 원문을 함께 제공하며, 다음 재무 장으로 넘어가지 않습니다. 3,000자나 6,000자 단위로 임의 발췌하지 않습니다.

AI에는 주석 제목 목록도 제공합니다. 현재 자료만으로 원천을 확인하지 못하면 관련 주석 ID를 요청하고, 해당 원문을 추가하여 다시 판단합니다. 추가 요청은 최대 두 차례로 제한합니다. 요청 한도·API 오류·인증 설정 문제는 공개자료 부족과 구분하여 표시합니다. 근거가 확인되면 자동 반영하고, 끝내 원천이나 범주를 확인하지 못한 항목은 ‘판단 보류’와 필요한 자료를 남깁니다. 서로 다른 범주가 섞인 통합계정은 금액을 임의 배분하지 않습니다.

‘계정재분류’의 판단 근거(H열)와 근거 주석·사업보고서 위치(U열)를 함께 확인하세요. U열 위치는 AI가 만들어 낸 번호가 아니라 실제 인용문이 들어 있는 원문에서 찾아 표시합니다. ‘공시원문근거’ 시트에는 조회한 번호별 주석과 사업보고서 절의 원문을 저장합니다. 긴 원문은 Excel 셀 크기 제한에 맞춰 이어지는 행에 저장하며, AI에 보내는 내용을 줄이지 않습니다. 원본 공시 링크도 함께 남깁니다.

주석 제목 형식이 인식되지 않는 문서는 감사보고서 전체를 사용합니다. 문서가 모델의 처리 용량을 넘으면 호출 오류로 남기며, 일부를 숨기고 자료 부족이라고 표시하지 않습니다. 실제 AI 실행에는 `.env`의 `OPENAI_API_KEY`와 `OPENAI_MODEL`, 원문 수집에는 `OPENDART_API_KEY`가 필요합니다. 키가 없는 테스트 결과는 실제 AI 판단 결과가 아닙니다.
